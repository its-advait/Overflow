# Contract invariants

Properties OverflowTreasury must hold after every transaction, with the code path that enforces each and the
test that exercises it. Tests run against Circle's compiled USDC v2.2 (`contracts/test/fixtures/usdc-v2_2`),
not a mock. Items marked **P1.5+** come from the spec but are not implemented yet (reservations); they are listed so the
invariant suite grows against this file.

## OverflowTreasury (`contracts/src/OverflowTreasury.sol`)

| # | Invariant | Enforced by | Covered by |
| --- | --- | --- | --- |
| T1 | For every node, `spent <= cap`. | `_authorize` reverts `OverBudget(n)` before charging; `raiseCap` only increases `cap`. | `test_OverBudget_child`, `test_sibling_spend_hits_parent_OverBudget`, `test_raiseCap_unblocks_OverBudget_node` |
| T2 | For every node, `spent >= sum of children's spent`. Every payment charges the signer's node and every ancestor by the same `value`. | The walk in `_authorize` charges each level up to the root. | `test_depth2_child_pays_increments_both`, `test_depth3_grandchild_pays_increments_all_three` |
| T3 | No partial charge. If `settle()` reverts for any reason (policy or token), no node's `spent` changes and no USDC moves. | All checks and charges run before the token call inside one transaction, so a token revert unwinds them. | `test_OverBudget_child` (spent unchanged), `test_settle_replay_reverts`, `test_blacklisted_payee_reverts_no_partial_charge` |
| T4 | The treasury balance never drops below `floor` through `settle()`. | `BelowFloor()` when `balanceOf(this) < value + floor`. `withdraw()` is owner-only and may go below the floor by design. | `test_BelowFloor` |
| T5 | `isValidSignature` returns `0x1626ba7e` only when `msg.sender == TOKEN` and only for the digest flagged by the running `settle()`. Outside `settle()`, and for every other caller, it returns `0xffffffff`. | Transient flag at `keccak256(abi.encode(APPROVAL_SALT, digest))` set and cleared around the token call; `view` + `tload` only, so nothing can set it from outside. | `test_gate_closed_outside_settle_for_usdc_and_others`, `test_isValidSignature_inside_settle_scoped_to_token_and_digest`, `test_flagClearedWithinSameTx`, `UsdcReal.t.sol::test_erc1271CallerIsUsdcProxy` |
| T6 | An agent's signed authorization sent straight to USDC never moves funds. The same signature settles only through `settle()`. | USDC's ERC-1271 path reaches `isValidSignature` with no flag set. | `test_direct_to_token_bypass_reverts`, `Adversarial::test_flagClearedWithinSameTx` |
| T7 | A node's authority is bounded by every ancestor: paused, expired, `maxPerCall`, restricted payees and remaining budget are all checked at each level. | The ancestor walk in `_authorize`, in the fixed order Paused, Expired, OverPerCall, PayeeNotAllowed, OverBudget. | `test_PayeeNotAllowed_inherited_from_restricted_ancestor`, `test_Paused_by_owner_blocks_subtree_then_unpause`, `test_pause_middle_node_blocks_grandchild`, `test_pauseChild_by_strict_ancestor_blocks_subtree`, `test_restrictedAncestorEnforcedThroughUnrestrictedMiddle` |
| T8 | A child never has more authority than its parent at creation: `cap`, `maxPerCall`, `expiry` within the parent's; depth at most 2; a restricted parent's child lists only payees the parent allows. | `createChild` checks before writing. | `test_ChildExceedsParent_*`, `test_TooDeep` |
| T9 | Each delegation (CreateChild or PauseChild struct hash) is consumed at most once and only before its deadline, and only the parent (or a strict ancestor for pause) can sign it. | `usedDelegation[structHash]`, deadline check, `ECDSA.recoverCalldata` against `parent.key` / ancestor walk. | `test_BadDelegation_*`, `test_NotAncestor_*`, `test_pauseChild_expired_deadline` |
| T10 | Node keys are unique and never the zero address, the owner or the treasury. | `_checkKey` in `createRoot` and `createChild`. | `test_KeyInUse_*` |
| T11 | Only two paths move USDC out: `settle()` via a flagged authorization, and the owner's `withdraw()`. No other function transfers tokens. | Contract surface. | `test_NotOwner_all_owner_functions`, `test_owner_setAllow_event_and_withdraw` |
| T12 | `settle()` is not reentrant. | OpenZeppelin `ReentrancyGuardTransient`. | Structural; USDC does not call back except the view `isValidSignature` |
| T13 | **P1.5+** The balance is at least `floor + reservedTotal` after every call, and `isValidSignature` is also valid for a live, unexpired reservation of that exact digest. | Not implemented. | None yet |
| T14 | A payee is either on the global allowlist, or an escrow made by `escrowFactory` whose `buyer()` is this treasury, whose `seller()` has `provenCheats == 0`, and whose `amount()` equals `value` exactly. Any payee with a proven cheat (direct payee or escrow seller) reverts `PayeeFlagged(seller)`. | Step 4 of `_authorize`: `allowlist[to]` then the flag check, else `isEscrow` / `buyer()` / `provenCheats` / `amount()` in that order (`PayeeNotAllowed(0)`, `PayeeFlagged`, `EscrowAmountMismatch`). `setEscrowFactory` is owner-only; a zero factory disables escrow payees. | `TreasuryEscrowPayee.t.sol`: `test_agentFundsEscrowThroughSettle`, `test_wrongAmountReverts`, `test_escrowWithDifferentBuyerReverts`, `test_flaggedSeller_escrowPathReverts`, `test_flaggedSeller_directPathReverts`, `test_escrowPayee_requiresFactorySet` |
| T15 | **Restricted nodes and escrows:** when the payee is an escrow, every restricted node on the path is checked against `nodeAllow[n][escrow.seller()]`, not the escrow address. Allowlisting a seller at delegation time therefore covers every per-order escrow of that seller, and an escrow whose seller is not allowed reverts `PayeeNotAllowed(n)` for the first restricted ancestor. | Step 5 uses `payee = escrow.seller()` (or `to` for a direct payment). | `test_restrictedNode_paysOnlyEscrowsOfAllowedSellers`, `test_restrictedNode_directSellerPaymentUsesSameAllow` |

## Escrow (`contracts/src/OverflowEscrow.sol`, `OverflowEscrowFactory.sol`, `MerkleLib.sol`)

Tier 1 (funding, reveal, accept, payout, timeout refund). Tests in `contracts/test/escrow/` run on real USDC; the
treasury is the buyer. The invariant suite is `contracts/test/invariant/EscrowInvariant.t.sol` (64 runs x depth 32).

| # | Invariant | Enforced by | Covered by |
| --- | --- | --- | --- |
| E1 | Exactly one terminal state: an escrow reaches at most one of `Settled` or `Refunded`, and nothing leaves a terminal state. | Every transition checks `status` first (`BadStatus`); `_payout` and `_refund` set the terminal status before transferring. | `test_finalize_twiceReverts`, `test_timeoutRefund_twiceReverts`, `test_terminalStatesAreExclusive`, `invariant_atMostOneTerminalState` |
| E2 | Zero USDC after the terminal state. | `_payout` sends `amount + bond` to the seller and any surplus to the buyer; `_refund` sends the whole balance to the buyer. | `test_payout_viaAccept`, `test_payout_surplusReturnsToBuyer`, `test_timeoutRefund_restoresTreasuryUsdc`, `invariant_zeroBalanceAfterTerminal` |
| E3 | Funds move only to the seller or the buyer (treasury). | Only `_payout`/`_refund` transfer, to `_t.seller` / `_t.buyer`. | `invariant_fundsOnlyToSellerOrBuyer` |
| E4 | Terms are immutable after creation and the address is the order: `create` reverts unless `termsHash` matches the 12 fixed fields, the CREATE2 salt is `keccak256(orderId, termsHash)`, and a clone initializes once (factory only). | `termsHashOf` check, `Clones.cloneDeterministic`, `_initialized` + `FACTORY` guards; the implementation is marked initialized in its constructor. | `test_create_predictedEqualsCreated`, `test_create_badTermsHashReverts`, `test_create_duplicateReverts`, `test_initialize_againReverts`, `test_implementation_cannotBeInitialized` |
| E5 | No payout before a valid reveal; the reveal is seller-only, before `revealDeadline`, and must open `keyCommitment`. | `accept`/`finalizePayout` require `Revealed`; `revealKey` checks `NotSeller`, `RevealWindowClosed`, `BadKey`. | `test_accept_beforeRevealReverts`, `test_reveal_afterDeadlineReverts`, `test_reveal_wrongKeyReverts`, `test_reveal_nonSellerReverts` |
| E6 | No refund after settlement and no settlement after a refund; the timeout refund needs `revealDeadline` to have passed with no reveal. | `claimTimeoutRefund` requires `Created`/`Funded` and `RevealWindowOpen`; payout paths require `Revealed`. | `test_timeoutRefund_beforeDeadlineReverts`, `test_timeoutRefund_afterRevealReverts`, `test_terminalStatesAreExclusive` |
| E7 | `accept` pays only on a signature from a node of `terms.buyer`, bound to this escrow: EIP-712 `{OverflowEscrow, 1, chainId, escrow}` over `Accept(bytes32 orderId)`, signer must satisfy `treasury.nodeOfKey(signer) != 0`. | `acceptDigest`, `ECDSA.recoverCalldata`, `NotBuyerNode`. | `test_payout_viaAccept`, `test_payout_viaAccept_childNode`, `test_accept_nonNodeReverts`, `test_accept_signatureForAnotherEscrowReverts` |
| E8 | A complaint without a structurally valid proof reverts: `i < chunkCount`, chunk length exactly 160, proof length exactly `expectedProofLength(i, chunkCount)`, leaves hashed with prefix `0x00` and nodes with `0x01` (an internal node can't pose as a leaf). Tier 1 then reverts `NotImplemented`. | `complainMismatch`/`complainPromise` + `MerkleLib`. | `test_complaint_*` incl. `test_complaint_internalNodeAsLeafReverts`, `MerkleLib.t.sol` golden vectors shared with `packages/recourse-crypto` |
| E9 | A flagged seller never receives a new payment: `provenCheats` on the factory, `PayeeFlagged` in the treasury on both the direct and the escrow path (T14). | `recordCheat` is escrow-only; `_authorize` step 4 reads `provenCheats`. | `test_recordCheat_onlyEscrows`, `test_flaggedSeller_escrowPathReverts`, `test_flaggedSeller_directPathReverts`, `test_flaggedSeller_otherSellersUnaffected` |

## How to extend

Add a row before changing the contract. Every row needs a code path and at least one test; "structural" is
acceptable only where no transaction can violate the property. The Foundry invariant suite
(`contracts/test/invariant/`) covers E1 to E3; T1, T2, T4 and T5 still need handlers.
