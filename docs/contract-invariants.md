# Contract invariants

Properties OverflowTreasury must hold after every transaction, with the code path that enforces each and the
test that exercises it. Tests run against Circle's compiled USDC v2.2 (`contracts/test/fixtures/usdc-v2_2`),
not a mock. All treasury rows are implemented. Foundry invariant suites (256 runs x depth 50, `contracts/test/invariant/`):
`TreasuryInvariant.t.sol` drives settle, reserve, facilitator execution, release, pause, delegation, escrow funding and payout, and
seller flags through one handler; `EscrowInvariant.t.sol` drives a single escrow. `contracts/test/fork/UsdcGate.t.sol` repeats the
USDC gate checks against live Base Sepolia USDC (`pnpm contracts:fork`). Gas: `docs/gas.md` (`pnpm contracts:gas`).

| T2 | For every node, `spent >= sum of children's spent`. | T13 | A reservation is a payment that passed every `settle()` check and was charged (same `_authorize`, same ancestor charges), stored once per digest with `validBefore <= now + reservationWindow`. `isValidSignature` returns valid to USDC for that exact digest only while `block.timestamp < validBefore`. | `reserve()` reuses `_authorize`; `ReservationActive`, `ReservationTooLong`; `isValidSignature` reads the stored reservation (still `view`). | `Reservations.t.sol`: `test_reserve_thenThirdPartySubmitsToUsdc`, `test_withoutReserve_directSubmissionFails`, `test_reserve_duplicateReverts`, `test_reserve_tooLongReverts_ownerCanWiden`, `test_reserve_runsEveryPolicyCheck`, `test_isValidSignature_reservationBranch_isViewAndTokenOnly`, `invariant_reservedTotalMatchesLiveReservations`, fork `test_fork_reservationLetsThirdPartySettle` |

## Escrow (`contracts/src/OverflowEscrow.sol`, `OverflowEscrowFactory.sol`, `MerkleLib.sol`)

Tier 1 (funding, reveal, accept, payout, timeout refund). Tests in `contracts/test/escrow/` run on real USDC; the
treasury is the buyer. The invariant suite is `contracts/test/invariant/EscrowInvariant.t.sol` (64 runs x depth 32).

| # | Invariant | Enforced by | Covered by |
| --- | --- | --- | --- |
| E1 | Exactly one terminal state: an escrow reaches at most one of `Settled` or `Refunded`, and nothing leaves a terminal state. | Every transition checks `status` first (`BadStatus`); `_payout` and `_refund` set the terminal status before transferring. | `test_finalize_twiceReverts`, `test_timeoutRefund_twiceReverts`, `test_terminalStatesAreExclusive`, `invariant_atMostOneTerminalState` |
| E2 | Zero USDC after the terminal state. | `_payout` sends `amount + bond` to the seller and any surplus to the buyer; `_refund` sends the whole balance to the buyer. | `test_payout_viaAccept`, `test_payout_surplusReturnsToBuyer`, `test_timeoutRefund_restoresTreasuryUsdc`, `invariant_zeroBalanceAfterTerminal` |
| E3 | Funds move only to the seller or the buyer (treasury). | Only `_payout`/`_refund` transfer, to `_t.seller` / `_t.buyer`. | `invariant_fundsOnlyToSellerOrBuyer` |
| E4 | Terms are immutable after creation and the address is the order: `create` reverts unless `termsHash` matches the 12 fixed fields, the CREATE2 salt is `keccak256(orderId, termsHash)`, and a clone initializes once (factory only). | `termsHashOf` check, `Clones.cloneDeterministic`, `_initialized` + `FACTORY` guards; the implementation is marked initialized in its constructor. | `test_create_predictedEqualsCreated`, `test_create_badTermsHashReverts`, `test_create_duplicateReverts`, `test_initialize_againReverts`, `test_implementation_cannotBeInitialized` |
| E5 | No payout before a valid reveal; the reveal is seller-only, before `revealDeadline`, and must open `keyCommitment`. | `accept`/`finalizePayout` require `Revealed`; `revealKey` checks `NotSeller`, `RevealWindowClosed`, `BadKey`. | `test_accept_beforeRevealReverts`, `test_reveal_afterDeadlineReverts`, `test_reveal_wrongKeyReverts`, `test_reveal_nonSellerReverts` |
| E6 | No refund after settlement and no settlement after a refund; the timeout refund needs `revealDeadline` to have passed with no reveal. | `claimTimeoutRefund` requires `Created`/`Funded` and `RevealWindowOpen`; payout paths require `Revealed`. | `test_timeoutRefund_beforeDeadlineReverts`, `test_timeoutRefund_afterRevealReverts`, `test_terminalStatesAreExclusive` |
| E7 | `accept` pays only on a signature from a node of `terms.buyer`, bound to this escrow: EIP-712 `{OverflowEscrow, 1, chainId, escrow}` over `Accept(bytes32 orderId)`, signer must satisfy `treasury.nodeOfKey(signer) != 0`. | `acceptDigest`, `ECDSA.recoverCalldata`, `NotBuyerNode`. | `test_payout_viaAccept`, `test_payout_viaAccept_childNode`, `test_accept_nonNodeReverts`, `test_accept_signatureForAnotherEscrowReverts` |
| E8 | A complaint without a structurally valid proof reverts: `i < chunkCount`, chunk length exactly 160, proof length exactly `expectedProofLength(i, chunkCount)`, leaves hashed with prefix `0x00` and nodes with `0x01` (an internal node can't pose as a leaf). | `complainMismatch`/`complainPromise` + `MerkleLib`. | `test_complaint_*` incl. `test_complaint_internalNodeAsLeafReverts`, `EscrowMismatch::test_internalNodeAsLeaf_reverts`, `test_tamperedCipherChunk_reverts`, `MerkleLib.t.sol` golden vectors shared with `packages/recourse-crypto` |
| E10 | **Tier 2 mismatch:** inside the challenge window, a ciphertext chunk proven under `rootCipher` whose decryption under `k_i = keccak256(revealedKey, i)` does not hash to the plaintext leaf proven under `rootPlain` refunds the whole balance (price + bond) to the buyer, records `provenCheats[seller]` on the factory and closes the escrow (`Refunded`). A matching chunk reverts `ChunkMatches`; nothing is refunded on an allegation alone. `RecourseCrypto.sol` and `packages/recourse-crypto` compute identical keys, keystream, ciphertext and roots (golden vectors). | `complainMismatch`: proofs, `RecourseCrypto.xorChunk`, status set before the factory/token calls, `recordCheat`. | `EscrowMismatch.t.sol`: `test_swappedChunk_refundsBuyerAndFlagsSeller`, `test_correctChunkComplaint_reverts`, `test_complaint_outsideWindow_reverts`, `test_complaint_afterRefund_reverts`, `test_flaggedSeller_blockedByTreasury`; `RecourseCrypto.t.sol` + `crypto.test.ts` |
| E11 | **Tier 3 promise:** inside the challenge window, a 160-byte record proven under `rootPlain` whose 65-byte signature does not recover (plain `keccak256(payload)`, no prefix) to `terms.sourceKey`, or whose big-endian uint64 timestamp is below `terms.minTimestamp`, refunds price + bond to the buyer and records the cheat. Only promised fields are checked; terms promising neither revert `NoPromise`; a kept promise reverts `PromiseKept`. A malformed signature counts as a wrong source. | `complainPromise`, `RecourseCrypto.splitRecord/recordTimestamp/payloadHash`, `ECDSA.tryRecover`, `_proveCheat`. | `EscrowPromise.t.sol`: `test_wrongSourceRecord_refunds`, `test_staleRecord_refunds`, `test_malformedSignature_countsAsWrongSource`, `test_validRecordComplaint_reverts`, `test_onlyTimestampPromise_ignoresSigner`, `test_noPromise_reverts`, `test_complaint_outsideWindow_reverts`; TS mirror `promiseBroken` in `crypto.test.ts` |
| E12 | **Bond:** `markFunded` needs balance >= price + bond; the bond returns to the seller with the price on payout and goes to the buyer on a proven cheat or a missed reveal (ghosting forfeits the bond without a cheat flag). | `markFunded` `Underfunded`, `_payout`, `_sweepToBuyer`. | `test_bond_returnsToSellerOnPayout`, `test_bond_goesToBuyerOnCheat`, `test_bond_goesToBuyerOnGhost`, `test_markFunded_requiresBondToo` |
| E13 | **Cheater flag:** every proven cheat increments `provenCheats[seller]` on the factory; the factory refuses `create()` (`SellerFlagged`) and the treasury refuses to pay the seller directly or through any escrow (`PayeeFlagged`, T-rules P1.4). Orders opened before the flag stay unpayable. | `OverflowEscrowFactory.create`, `recordCheat`; treasury `_authorize`. | `test_flaggedSeller_cannotCreateOrBePaid`, `test_cheatCountAccumulatesAcrossOrders`, `TreasuryEscrowPayee::test_flaggedSeller_escrowPathReverts`, `EscrowMismatch::test_flaggedSeller_blockedByTreasury` |

## How to extend

Add a row before changing the contract. Every row needs a code path and at least one test; "structural" is
acceptable only where no transaction can violate the property. The Foundry invariant suite
(`contracts/test/invariant/`) covers E1 to E3; T1, T2, T4 and T5 still need handlers.
